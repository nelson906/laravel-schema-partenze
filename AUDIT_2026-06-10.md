### ❌ Ancora aperti

#### 🔴 1. `is_active` non applicato al login (invariato dal 23/05)

`app/Http/Requests/Auth/LoginRequest.php:45`:

```php
if (! Auth::attempt($this->only('email', 'password'), $this->boolean('remember'))) {
```

Nessun controllo su `is_active` in tutto `app/Http` (verificato con grep: il campo compare solo nel CRUD di `UserController`). Il toggle "Disattiva utente" in admin è **cosmetico**: l'utente disattivato entra comunque.

**Fix (10 minuti):**

```php
if (! Auth::attempt(
    array_merge($this->only('email', 'password'), ['is_active' => true]),
    $this->boolean('remember')
)) {
```

Più logout forzato per sessioni già attive: middleware che fa `Auth::logout()` se `! $request->user()->is_active`. Aggiungere test in `AccessControlTest`.

#### 🔴 2. Path traversal in `databaseRestore()` (invariato dal 23/05)

`app/Http/Controllers/SuperAdmin/ArubaToolsController.php:347-356` passa `$request->input('filename')` a `SystemOperations::restoreDatabase()`, che concatena senza validazione:

```php
$filepath = storage_path('backups/database/'.$filename);  // riga ~252
```

Nessun `basename()`, nessuna whitelist estensione. Un `filename=../../../.env` supera il check `File::exists()`. Mitigato dal middleware `super_admin`, ma il fix costa 2 righe:

```php
$filename = basename($filename);
abort_unless(str_ends_with($filename, '.sql'), 422);
```

## Nuovi rilievi

### 🟡 3. Dipendenza Tailwind contraddittoria in `package.json`

Convivono `tailwindcss: ^3.1.0` e `@tailwindcss/vite: ^4.0.0`. Il build reale usa la v3 via PostCSS (`postcss.config.js` → plugin `tailwindcss`); il plugin Vite v4 **non è importato da nessuna parte** (verificato in `vite.config.js`). Dipendenza morta che prima o poi confonderà un `npm update`.

**Fix:** `npm uninstall @tailwindcss/vite`.

### 🟡 4. File morti della registrazione rimasti su disco

Route rimosse, ma restano (entrambi **untracked** in Git):

- `app/Http/Controllers/Auth/RegisteredUserController.php`
- `resources/views/auth/register.blade.php` — referenzia `route('register')` che non esiste più: se mai renderizzata, eccezione immediata

**Fix:** cancellare entrambi.

### 🟡 5. `.ftp-deploy-sync-state.json` (1,8 MB) non in `.gitignore`

Untracked ma presente in root. È stato di deploy, non sorgente; rischio commit accidentale da 1,8 MB.

**Fix:** aggiungere `.ftp-deploy-sync-state.json` a `.gitignore`.

### 🟡 6. jQuery 3.6.0 + jQuery UI 1.12.1 da CDN senza SRI

`resources/views/quadranti/index.blade.php:316-318`. Tre problemi: (a) jQuery UI 1.12.1 ha CVE XSS noti, corretti in 1.13.x; (b) nessun attributo `integrity` sugli script CDN; (c) stack misto col resto dell'app (Vite/Alpine) — già notato il 23/05 come 2.5, qui si aggiunge il tema versione/SRI.

**Fix minimo:** aggiornare a jQuery UI 1.13.3 e aggiungere SRI. Fix strutturale (rimuovere jQuery) rimandabile.

### 🟢 7. Password MySQL sulla riga di comando

`SystemOperations::backupDatabase()`/`restoreDatabase()` passano `-p'password'` a mysqldump/mysql: visibile in `ps aux` per la durata del comando. Su hosting condiviso Aruba è un leak teorico ma reale. Alternativa: file di configurazione temporaneo `--defaults-extra-file`.

### 🟢 8. Route legacy `storage-link.index`

`ArubaToolsController::storageLinkIndex()` (riga 390) fa solo `redirect()->route('aruba.admin.permissions')`. Route + metodo + 2 voci di menu sopravvissute a un refactoring. Rimovibili.

### 🟢 9. Naming route ancora misto

`admin.users.*` vs `aruba.admin.*` (ordine invertito dei segmenti). Già segnalato il 23/05 (2.3), invariato. Cosmetico.
